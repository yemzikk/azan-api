01 / GETTING STARTED

From request to prayer times.

Find a timetable in the locations index, then use its exact identifier to request a day, month, year, or the complete dataset.

BASE URLhttps://api.azantimes.in
JavaScript
const base = 'https://api.azantimes.in';
const location = 'Kuttiady_Assembly_Constituency';
const response = await fetch(
  `${base}/v1/timesheets/${encodeURIComponent(location)}/today.json`
);
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const times = await response.json();
console.log(times.subh); // '4:58 AM' in this example
i

These endpoints serve generated timetable files. Always check the returned date before presenting a record as today’s prayer times.

04 / RESPONSE FORMAT

A familiar shape, every time.

Prayer times use 12-hour local time in India (Asia/Kolkata, UTC+05:30). Field names follow the source timetables.

05 / INTEGRATION NOTES

A few things to build around.

01

Choose the right timetable

Some locations include different sources or schools of jurisprudence. Preserve the source name and let people select the timetable they follow.

02

Check dates, then cache

Files are generated ahead of serving. Validate their dates and cache a month or year for date-based lookups instead of repeatedly fetching daily data.

03

Handle unavailable data

Check the HTTP status before parsing JSON. Missing files can return a 404 or an HTML error page. Keep a helpful fallback in your interface.

04

Respect the local schedule

Timetable times are local to their location. Do not reinterpret them in the device’s timezone. Confirm local mosque timings for congregation times.
